# ADR-005: 좋아요 상태 전이와 메타 카운터의 원자성

- Issue: #184
- 상태: 구현 및 작성자 MySQL 검증 완료 / 독립 검토 대기
- 기준: develop cf49788269fe8cfc03a9ca160c87dcabde82494c

## 문제
좋아요 원본과 카운터는 독립 쓰기이며 취소는 집계를 감소시키지 않는다. 비활성 원본의 재활성화도 막혀 있다. SELECT 후 INSERT는 동시 요청에 안전하지 않다.

## 결정
기존 ItemFavoriteService의 두 공개 쓰기 메서드에 READ_COMMITTED 트랜잭션을 적용한다. 항상 item PK 행 FOR UPDATE → 기존 좋아요 조회 → 상태 변경 → 메타 증감 순서다. 상품 행 잠금은 트랜잭션 종료까지 유지된다. 별도 Redis 락이나 JVM 락은 없다. 여러 앱도 같은 InnoDB 행 잠금을 사용한다.

- 없음 + 추가: INSERT, +1.
- 비활성 + 추가: 활성화, +1.
- 활성 + 추가: AlreadyPushItemFavorite (기존 정책).
- 활성 + 취소: 비활성화, -1.
- 비활성 + 취소: 성공/no-op (기존 반복 취소 정책 유지).
- 없음 + 취소: NotPushItemFavorite (기존 정책).

동시에 도착한 요청은 상품 잠금 획득 순서의 직렬 실행으로 정의한다. HTTP 도착 순서는 보장하지 않는다. 취소/추가 중 어느 것이 최종 상태가 되든 활성 원본 수와 집계는 같아야 한다.

원본 INSERT/조건부 UPDATE와 카운터 증감은 각각 영향 행 수 1을 요구한다. 메타 누락/중복·0인 카운터 감소·DB 오류는 예외로 전체 롤백한다. MySQL 8.0.16+의 CHECK로 NULL 논리 키를 방어하며 컬럼 타입은 유지한다. 신규 UNIQUE(user_id,item_id)는 애플리케이션 외부에서 중복 원본 생성도 차단한다. 기존 NULL 키/중복은 자동 삭제하지 않고 마이그레이션 실패로 드러낸다.

## 대안과 비용
- 트랜잭션만: 원자성은 해결하지만 최초 중복 INSERT 경쟁은 남는다.
- UNIQUE + 조건부 DML만: 가능하지만 최초 INSERT 경합·재활성화·취소의 결과 매핑이 더 복잡하다.
- 메타 행 잠금: 메타가 없거나 중복인 기존 데이터의 잠금 기준이 불명확하다.
- 상품 PK 잠금(채택): 항상 존재하는 부모를 잠금 기준으로 삼고 기존 Service/Mapper만 수정한다. 동일 상품의 여러 회원도 직렬화되므로 인기 상품 쓰기 처리량을 제한한다. 이 PR에서 성능 향상을 주장하지 않는다.
- Redis/비동기 집계: 운영 의존과 복구 계약을 늘리므로 제외.

## 데이터·배포
기존 item/item_favorite/item_favorite_meta 테이블은 Flyway 전체 생성 대상이 아니다. 마이그레이션 전 모든 앱/배치/관리자 쓰기를 중단하고 백업, 테이블 엔진·키·FK·중복을 확인해야 한다. 중복 원본은 보존할 행과 활성 상태를 운영자가 결정한 후 정리한다. 제약 추가만으로 오래된 카운터는 복구되지 않는다. scripts/maintenance/reconcile-item-favorite-count.sql은 점검 결과 검토 후 유지보수 트랜잭션 부분을 실행한다. 원본 중복/누락 메타/중복 메타가 있으면 먼저 해결하며 이 스크립트는 데이터를 임의 삭제하지 않는다. 오래된 바이너리와 새 바이너리의 동시 쓰기는 금지한다.

## 검증
실제 MySQL + Spring 트랜잭션 프록시 + 실제 Mapper XML로 검증한다. 테스트 메서드에는 자동 롤백을 두지 않고 별도 JDBC 연결로 커밋/롤백 상태를 확인한다. 원본 INSERT 뒤 메타 UPDATE를 DB trigger SIGNAL로 실패시키고 원본 롤백을 관찰한다. 모든 동시 작업 Future의 결과를 수집해 예상 밖 오류를 숨기지 않는다. 실행 결과는 issue-184-review.md를 따른다.

## 한계
DB 직접 쓰기/트리거/외부 서비스가 이 잠금·카운터 계약을 우회하면 집계 일치를 보장할 수 없다. FK는 배포 대상 실제 스키마를 확인해야 하며 이 변경은 회원 삭제·상품 생성의 별도 원자성 문제를 다루지 않는다. 독립 Verifier 실행과 운영 배포는 이 문서 작성으로 완료되지 않는다.
